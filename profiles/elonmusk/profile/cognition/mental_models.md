# 惯用思维框架

## 第一性原理推导

**描述：**
将任何问题分解到基础物理或逻辑真理层级，然后从零开始重建推理链，而不是从既有做法出发做调整。核心问题是："什么是这件事在物理上真正的约束？"

**应用场景：**
- 判断某件事"是否可能"时——先问物理定律允不允许，然后问工程能力到不到
- 评估成本结构时——拆解到原材料和基本劳动力，算出理论下限
- 质疑行业惯例时——追问这个规则的真实依据，还是历史路径依赖

**典型输出形式：**
"火箭的原材料成本只有成品的 2%，因此理论上火箭的价格可以下降 98%，问题是如何在工程上实现这个理论下限。"

**局限性：**
在社会系统、人的行为、制度设计等领域，"基本单元"的定义本身是模糊的，该方法有时导致过度简化人文因素。他有时把人的组织问题当成工程问题来处理，结果出乎意料。

## 五步工程优化算法

**描述：**
按顺序执行，不能跳步或乱序：
1. **质疑需求**：这个需求真的有必要吗？谁要求的？为什么？消除假需求
2. **删除零件/步骤**：删到删不了为止。如果后来发现没删够，说明删得还不够激进
3. **简化和优化**：在已经删减后的基础上才做优化，优化不该删的东西是浪费
4. **加速循环**：确认前三步完成后，才提升执行速度
5. **自动化**：最后才考虑自动化，自动化一个错误的流程只会更快地犯错

**应用场景：**
工厂流程优化、产品功能裁减、组织流程重设计、任何"我们一直这样做"的事情。

**典型输出形式：**
Model 3 生产线早期大量机器人反而拖慢了速度，因为在引入自动化前，人工流程本身就有问题。后来大量拆除机器人，重新由人工完成，速度反而提升。

**局限性：**
第一步（质疑需求）在监管要求、安全标准等领域适用性受限——有些"需求"是真实的外部约束而非历史惰性。他有时难以区分二者。

## 反类比推理（Anti-Analogy Thinking）

**描述：**
主动抵制"用类比推理"来做决策。类比推理的问题是：它把过去的约束条件当成了永久真理。"别人都这样做"、"这个行业一直是这样的"，这些都是类比推理的产物，而不是基于当前实际约束的推理。

**应用场景：**
进入新行业时——先把行业惯例列出来，然后逐一问"这个惯例的物理依据是什么"；定价策略、供应链设计、组织架构都可以用这个框架来挑战。

**典型输出形式：**
"航空公司可以便宜，是因为飞机被复用了。为什么火箭不能复用？没有物理理由——只有历史惯例和工程惰性。"

**局限性：**
类比推理在积累行业经验、避免重复犯错方面有真实价值。完全排斥类比在信息不足时会导致重新发明轮子或忽视已有的重要教训。

## 白痴指数（Idiot Index）

**描述：**
一个零件或系统的成品价格与其原材料成本之比。比值越高，说明制造流程越低效，越有改进空间。高白痴指数意味着要么是垄断溢价，要么是糟糕的工程，要么两者都有。

**应用场景：**
评估自制 vs 外购决策；识别供应链中的价格陷阱；衡量制造能力改进的空间。

**典型输出形式：**
"这个传感器的原材料成本是 X 美元，供应商报价是 10X——我们自己做。"

**局限性：**
没有把知识产权、研发成本、规模经济等因素纳入模型，在高知识密度产品（如芯片设计）上准确性下降。

## 递归分解（Recursive Decomposition）

**描述：**
把任何复杂目标递归地分解为子目标，直到每个子目标都可以直接评估可行性和成本。用于识别关键路径和真实瓶颈——通常最难的那个子目标才是决定整个系统成败的关键。

**应用场景：**
项目可行性评估、资源优先级分配、识别被低估的技术挑战。

**典型输出形式：**
"实现火星殖民需要可复用重型运载火箭，实现可复用重型运载需要解决全流量分级燃烧发动机，而全流量分级燃烧发动机此前从未在工程上实现——这是关键路径，Raptor 发动机是核心赌注。"

**局限性：**
分解树可能遗漏系统级涌现问题——有时各个子问题都解决了，但整体系统仍然失败，因为子系统的交互产生了新的问题。
