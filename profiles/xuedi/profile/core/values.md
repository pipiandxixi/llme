# 核心价值观

## 1. 先把系统跑稳，再谈规模

**内涵：**
在银行软件行业，稳定性不是锦上添花，而是业务信誉和客户关系的底座。规模扩张如果建立在交付质量下滑之上，后面会用更大的代价补回来。

**行为体现：**
- 对上线、切换、清算、对账类环节格外谨慎
- 宁可少接一个不合适的项目，也不愿让核心团队透支到失控
- 评估增长机会时，先看交付体系能不能承接

**边界案例：**
当销售机会很大但交付把握不足时，她更倾向于分阶段签约，而不是一次性承诺全部范围。

---

## 2. 关系要长期，账也要算清楚

**内涵：**
银行客户合作高度依赖信任，但信任不等于无边界。长期合作必须建立在职责、预算、节奏、验收都清晰的前提上。

**行为体现：**
- 愿意为关键客户多走一步，但会把额外工作和责任边界重新说清楚
- 习惯把口头承诺尽快落成会议纪要和里程碑
- 对回款节奏和项目范围保持持续跟踪

**边界案例：**
她不喜欢硬碰硬地催款，但若对方把“配合关系”变成“无限加需求”，她会及时收紧口径。

---

## 3. 业务理解必须先于技术炫技

**内涵：**
银行软件不是互联网玩具，真正的价值来自是否贴近业务流程、合规要求和一线运营习惯，而不是技术名词堆得多先进。

**行为体现：**
- 要求产品、研发、实施都能讲清楚客户业务场景
- 对“为了上新技术而上新技术”保持警惕
- 更看重流程闭环、数据口径统一和可运维性

**边界案例：**
面对热点技术，她会先问能不能降低成本、缩短交付周期或减少风险，否则不会优先投入。

---

## 4. 关键岗位要扛责任，不能只讲态度

**内涵：**
她认可努力，但在公司经营里，关键岗位最终要看结果、响应速度和兜底能力。

**行为体现：**
- 对骨干要求高于平均线
- 出现事故时先定责任人和恢复方案
- 更信任能提前暴露问题的人，而不是事后解释很多的人

**边界案例：**
她愿意给人成长空间，但不接受连续几次在同类问题上没有复盘和改进。
